# Controller navigation ownership

Core117 separates controller Menu navigation from gameplay input admission. In Core116, the literal polling path gated every controller action on network readiness, so Menu could not open Pause while connecting/reconnecting/offline, during selection, or during a server gameplay freeze. Keyboard Escape and touch Menu retained that navigation path. This was a source-level discrepancy; it was not observed on a physical controller.

The GameVC now polls the selected controller's Menu release edge before deriving gameplay eligibility. It uses the existing normal Pause presenter and canNavigateMenus guard. Background, detached-window and covered-modal states cannot open another menu. Reset boundaries sample the actual button state; a held Menu stays consumed, an already-up button preserves the next fresh press, and a missing/replaced controller cannot manufacture a press. Releases continue to be observed while another modal owns UI.

The original strict gameplay neutral-rearm gate remains unchanged, including Menu in its physical neutral test. Menu is excluded only from the later gameplay action snapshot because the navigation owner has already handled it. Other controller mappings, touch layout, simulation, bindings, network and renderer behavior are unchanged. A same-frame Pause presentation suppresses the remainder of the game's input poll.

The regression command is `python3 smoke_native_controller_navigation.py`. It compiles production pure helpers plus the literal extracted GVC navigation/reset/presentation/polling/gate/dispatch sections and horn-input owner, using authored platform spies. It tests normal/offline/frozen/selection navigation, held/released and controller-identity boundaries, same-frame modal suppression and gameplay jump/fire/horn/siren neutral rearming. The historical negative is `python3 smoke_native_controller_navigation.py --baseline /path/to/Core116 --expect-historical-drop`; it exercises the old real polling path, rather than merely calling performBinding(.pause), which hid the gap.

`--prepare-only` writes an immutable carrier and source manifest without invoking a compiler. Host tests, full SDK builds and actual controller/UI acceptance are separate evidence stages. No physical-controller or complete retail-controls claim follows from the extracted-source carrier. Menu/Start mapping remains edition-qualified as documented in CORE_INPUT_BINDINGS.md.
