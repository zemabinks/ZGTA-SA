Boarding and exit previously rounded every animation phase up to a rendered frame and discarded its extra elapsed time. Driver controls wait for the seated phase; normal exit waits for the standing phase. As a result, the same clip plan could grant controls or release a vehicle at different times on15Hz and120Hz displays.

`NativeRiderPlayback` now carries ordinary elapsed time into each next queued phase. A finite phase count bounds missing or zero-duration clips. Each crossed boundary captures its exact outgoing phase end and advances the capture serial; the returned frame exposes the latest capture if several boundaries cross at once. Completion releases the held door once. Transition blending and the first seated update receive only the time after the final boundary. A nonzero seat-turn target likewise receives only that seated portion, using the existing response curve.

Invalid, negative or suspension samples above.5s hold the clock and never create a later backlog. No animation duration, door curve, seat geometry or retail constant changes. The renderer's separate.1s sample cap is unchanged. Its behavior below10 rendered frames per second remains a separate limitation. The remaining Euler seat-turn/seated response curves are not claimed to be identical across frame schedules.

This intentionally differs from the archived browser's frame-rounded queue timing. Existing historical browser/native vertex comparisons remain valid for their earlier implementation and tested schedules. They do not establish equal elapsed timing after this correction; no golden output is rewritten to conceal that difference. The planner, clip selection and exact phase-end capture semantics remain the reference for compatibility.
