# Native legacy UDP transport

This source module provides SA-MP's legacy RakNet UDP transport to the native
app through a small asynchronous C ABI. It is not a complete game client.
An accepted RakNet connection does not establish account login, class
selection, spawn, world synchronization, 0.3.DL models or playable gameplay.
The Swift application owns those protocol/gameplay systems and their tests.

## Build

From the project root on a Mac with Go1.26.4 or newer and Xcode:

```sh
python3 build_samp_transport.py --test
```

The script runs host race/UDP tests, builds host, iPhone and universal arm64/x86_64 Simulator static
archives, links actual Apple SDK C probes and executes the host C ABI probe.
All archives, headers generated by cgo, caches, logs and reports stay in
`local-only/native-samp/`. Nothing is downloaded by this module's Go build;
its only Go dependencies are the standard library.

Link `libzgtasa_samp.a` for the actual platform, add `native-samp/include` to
Swift's include paths and link `resolv`, CoreFoundation and Security. Import
the `ZGTASAMPTransport` module. The installed module map imports the independent
stable C header rather than a platform-specific generated cgo header.

## Ownership and events

`zgtasa_samp_open` returns a monotonically increasing process-local handle
immediately. DNS, UDP connection/cookie exchange, reliability, retransmission
and reads run on Go workers. The input buffers are copied during every call;
no Swift pointer or callback is retained by Go. Closing a handle removes it
immediately and asynchronously drains/closes its socket. Old workers cannot
publish into a new handle. The Swift connection generation must also reject
events from a replaced connection.

Poll one consumer per handle. The result is0 for no event,1 for raw accepted
packet(ID34),2 for a raw application packet, or3 for a terminal UTF-8 error.
Application packets include authentication(ID12) before acceptance and
RPC(ID20). The bridge does not fabricate authentication or spawn success.
A0-capacity size probe returns−2 with the required length while retaining the
event; retry with an adequate owned buffer. The accepted snapshot has a
separate non-consuming getter. The exact ABI and error values are documented
in `include/zgtasa_samp.h`.

Client-to-server datagrams use the legacy port-keyed cipher; server-to-client
datagrams are read as the protocol's plain reliability frames. Outgoing sends
specify the original reliability values6…10 and ordering channel0…31. The
bridge does not serialize game state or convert coordinate systems.

The transport uses independent ordered/sequenced counters, uint16 sequence
wrapping, acknowledgement/retry handling and bounded incoming split assembly.
The bridge sends a reliable internal RakNet ping every5s after acceptance,
so a broken UDP path eventually exhausts reliable retries even if movement
uses unreliable sync. A quiet-server50-packet UDP test guards native uplink
against the original100ms polling delay.

## Bounds and limitations

- Maximum64 handles,128 queued sends per handle,256 queued events/4MiB, and
  a1MiB maximum received event. Overflow becomes a visible terminal error.
- Outgoing packets are1…8191bytes because the underlying frame's payload
  bit count is uint16. Outgoing fragmentation is not implemented; incoming
  assembly is supported by the transport. Never truncate an oversized RPC.
- IPv4 hosts only, with context-bounded DNS/initial acceptance. Protocol text
  encodings and account/password UI belong to the application.
- Remote rejection/close, cancellation, retry exhaustion and bounded queues
  are surfaced; the application still needs reconnection policy, lifecycle
  suspension and actual world/gameplay acceptance.
- No custom launcher, anti-cheat emulation, ban evasion, CEF, voice or 0.3.DL
  asset downloader is implemented here. Server requirements remain applicable.
