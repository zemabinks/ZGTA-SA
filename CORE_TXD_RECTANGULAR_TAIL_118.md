# Rectangular omitted BC mip tails

The native TXD reader rejected available stock dictionaries because it required both mip dimensions to be below four before accepting an omitted compressed tail. Actual PC dictionaries also contain trailing empty 4×2, 4×1 and 8×2 records. The rejected 8×2 case has 16 texels, so a pixel-area-below-16 rule would also be incorrect.

The reader now accepts a zero-byte trailing BC mip after a stored base when either dimension is below one 4×4 block. It retains that level as `rgba8 == nil`, with zero encoded bytes. It does not invent pixels. Empty bases, raw-format empty levels, empty compressed levels whose two axes are at least four, and stored data following an empty level still fail. Nonzero records still require their complete block-rounded encoded size. Dimension, count and decoded-byte limits are unchanged.

The compiler-free prepared-resource inventory covered 2,889 distinct TXDs and 30,760 native texture headers. It found 606 rectangular records rejected by the previous condition in 278 dictionaries referenced by 1,618 selected stock model IDs. There were no empty bases, empty raw records or resumed stored chains in that inventory. These are header observations, rather than successful native import or rendering results. Five CJ input dictionaries additionally require their existing, separately validated outer IMG-sector trim; the strict TXD decoder's stream-boundary policy is unchanged.

The existing native CPU decoder reproduced an actual dictionary rejection while 14 representative DFFs matched the independent parser and 13 COL files decoded. That failed TXD result remains retained. The new 49 authored cases cover all three supported BC formats, observed rectangles, transposes and longer strips, plus base, raw, non-tail and stored-after-empty rejection. Transposed and longer cases establish the explicit parser policy; those shapes were not all observed in the inspected resources. The old decoder rejects all 30 new positive fixtures and correctly rejects the 19 malformed negatives. Every stored mip is compared against the independent pixel oracle; absent levels retain no RGBA hash or allocation.

The affected gate, `python3 test_native_renderware_txd.py --no-corpus`, passed all 557 authored cases (344 accepted and 213 correctly rejected) after one two-file CPU compile. The unchanged 13-dictionary owner sample then passed, including the original rejection. All 278 affected stock dictionaries passed native CPU decoding and independent Pillow pixel comparison in 56.9 seconds. Coverage was extended to all 2,408 distinct stock dictionaries: 2,130 additional native executions plus the 278 already verified records, retained only with matching source/binary/file stamps. This passed in 254.1 seconds at nice15, covering 29,625 decoded textures, 74,950 stored mips and 9,984 explicitly absent tails. Original size/SHA/CRC, mutation guards, per-file byte limits and unchanged executable/source identities were checked. Actual static-model preparation, named-texture resolution, GPU registration, collision-world behavior and normally joined gameplay remain separate acceptance steps. This correction does not establish complete retail rendering parity.

The combined Core118 source subsequently passed full iPhone Release and universal Simulator Debug builds. A normal installed-package repair retained installed mode and activated 6,781 resources. Ordinary official open.mp join, CJ0 Spawn, Pause/Resume and a small touch-camera orbit passed. Full native scene captures show the textured bed1700 from an affected dictionary and cone1238; the server's ordinary creation/join/Spawn callbacks corroborate the scene. No client pose, skin, packet acknowledgement or cache seeding was used. This establishes bounded native preparation/GPU/gameplay acceptance for that selected object, while direct collision contact, all-model rendering, physical hardware and retail parity remain open.
